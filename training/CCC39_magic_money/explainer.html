LEVEL 1

The first amount no coin pays

Each currency has a handful of coin values. Find the smallest positive amount that is not itself a coin value, i.e. the first amount you cannot hand over as a single coin.

Input N (currencies), C (coins per currency), then N lines of C sorted coin values.
Output one line per currency: the smallest positive integer that is not a coin.
▶ COUNTING UP THROUGH THE COIN SET

KEY IDEA

Put the coins in a set and walk m = 1, 2, 3, ... until m is missing. At most C + 1 checks per currency.

Complexity: O(N·C)

PITFALLS

  • The answer can be C + 1 (or bigger) when the coins are 1..C.
  • One answer per line, file ends with a single newline.
CORE OF solution.py
def solve(text):
    tok = text.split()
    n, c = int(tok[0]), int(tok[1])
    out = []
    pos = 2
    for _ in range(n):
        coins = set(map(int, tok[pos:pos + c]))
        pos += c
        m = 1
        while m in coins:
            m += 1
        out.append(str(m))
    return "\n".join(out) + "\n"
LEVEL 2

Pay with exactly two coins

Now every currency also gets a list of amounts. Pay each amount with exactly two coins of that currency; the same coin value may be used twice. Every amount is payable and any valid pair is accepted.

Input N, C, A on three lines, then per currency a line of C coins and a line of A amounts.
Output one line per amount: two coin values separated by a space.
▶ TWO-SUM SCAN, SMALLEST COIN FIRST

KEY IDEA

Classic two-sum: keep the coins in a set; for an amount t scan coins ascending and stop at the first x whose partner t − x is also a coin. Ascending order prints the smaller coin first, which reproduces the example exactly.

Complexity: O(A·C) per currency

PITFALLS

  • C and A are given once at the top, not per currency.
  • x == t − x is allowed (2 2); a set lookup handles it naturally.
  • check.py accepts any valid pair.
CORE OF solution.py
def solve(text):
    tok = text.split()
    n, c, a = int(tok[0]), int(tok[1]), int(tok[2])
    pos = 3
    out = []
    for _ in range(n):
        coins = sorted(set(map(int, tok[pos:pos + c])))
        pos += c
        amounts = tok[pos:pos + a]
        pos += a
        cs = set(coins)
        for s in amounts:
            t = int(s)
            for x in coins:  # ascending -> smaller coin printed first
                if (t - x) in cs:
                    out.append("%d %d" % (x, t - x))
                    break
            else:
                raise ValueError("no pair for %d" % t)
    return "\n".join(out) + "\n"
LEVEL 3

Fewest coins for 1..100

Back to the level-1 input, but every currency now contains the coin 1 and the supply is unlimited. For each currency print, for every amount 1 to 100, a way to pay it with the fewest coins. Greedy fails on odd coin systems, so this needs dynamic programming.

Input N, C, then N lines of C coin values.
Output N·100 lines QxV QxV ... (Q coins of value V).
▶ FILLING THE DP TABLE

KEY IDEA

dp[a] = 1 + min(dp[a − c]) over all coins c ≤ a, filled from 1 up to 100. Remember which coin won (last[a]) and walk back a → a − last[a] to list the coins. Trying coins ascending with a strict < reproduces the example byte for byte.

Complexity: O(100·C) per currency

PITFALLS

  • Greedy is wrong: 6 with {1,3,4} greedy gives 4+1+1 (3 coins), optimal is 3+3.
  • Exactly N·100 lines.
  • check.py re-checks minimality with an independent DP.
CORE OF solution.py
def min_coins_table(coins):
    """dp[a] = fewest coins for amount a; last[a] = a coin used (smallest on ties)."""
    inf = float("inf")
    dp = [0] + [inf] * LIMIT
    last = [0] * (LIMIT + 1)
    for a in range(1, LIMIT + 1):
        for c in coins:  # ascending; strict '<' keeps the smallest coin on ties
            if c <= a and dp[a - c] + 1 < dp[a]:
                dp[a] = dp[a - c] + 1
                last[a] = c
    return last
LEVEL 4

Fewest coins for a billion

Same question as level 3, but the amounts go up to about 10⁹, so a table over the amount is impossible. Coins are at most 20 and coin 1 is always present; any optimal answer is accepted.

Input N, C, A, then per currency a line of C coins and a line of A amounts.
Output one line QxV ... per amount with the fewest coins.
▶ SMALL TABLE + PEEL THE BIG COIN

KEY IDEA

Let M be the largest coin. Among any M smaller coins some subset sums to a multiple of M (pigeonhole on prefix sums), and that subset can be swapped for no more M-coins. So for amounts ≥ M² an optimum always contains an M: f(x) = f(x − M) + 1. Build the DP once up to M² + M, peel k copies of M so the rest lands in [M², M² + M), and read the rest from the table.

Complexity: O(C·M²) per currency + O(M²) per amount

PITFALLS

  • Never loop over the amount or allocate a table that large.
  • Counts reach tens of millions; keep integers.
  • check.py proves optimality independently with Dijkstra over residues mod M.
CORE OF solution.py
def build_table(coins):
    """Fewest-coins DP for amounts 0 .. M*M + M - 1 (M = largest coin)."""
    m = coins[-1]
    size = m * m + m
    inf = float("inf")
    dp = [0] + [inf] * (size - 1)
    last = [0] * size
    for a in range(1, size):
        best = inf
        bc = 0
        for c in coins:  # ascending, strict '<' -> smallest coin on ties
            if c > a:
                break
            v = dp[a - c] + 1
            if v < best:
                best = v
                bc = c
        dp[a] = best
        last[a] = bc
    return last

def construct(amount, coins, last):
    m = coins[-1]
    base = m * m
    cnt = {}
    if amount >= base + m:
        k = (amount - base) // m  # for x >= M^2 an optimal solution uses a largest coin
        amount -= k * m
        cnt[m] = k
    while amount:
        c = last[amount]
        cnt[c] = cnt.get(c, 0) + 1
        amount -= c
    return " ".join("%dx%d" % (cnt[v], v) for v in sorted(cnt, reverse=True))
LEVEL 5

Paying from a limited vault

The vault now holds a fixed number of coins of each value (100x1 means 100 coins of value 1). Pay each amount (up to ~3·10⁸) with the fewest coins without exceeding the stock. Amounts are independent: paying one does not empty the vault for the next.

Input N, C, A, then per currency an inventory line of C items QxV and a line of A amounts.
Output one line QxV ... per amount, fewest coins, within inventory.
▶ ONE FREE COIN TYPE, EVERYTHING ELSE BOUNDED

KEY IDEA

Exchange argument: if a smaller type a is used at least v_b times while a bigger type b still has v_a coins left, swapping v_b coins of a for v_a coins of b saves coins. So in an optimum at most one type j is "free": types above it are within Vmax − 1 of their stock and types below it are used fewer than v_j times.

For each choice of j (or none) build one small bounded knapsack per currency over the bounded "extra" coins. An amount is answered by scanning the residue class mod v_j, pre-sorted by v_j·g[s] − s, and taking the first entry that keeps j within stock.

Complexity: ~7 knapsacks of ~2k states per currency, then ~O(C) lookups per amount

PITFALLS

  • QxV is count first, value second, in input and output.
  • The free type can be any type, so every j (plus "none") must be tried; keep j's count within [0, u_j].
  • Our example output differs from the official one only in tie-breaking: every line has the same coin count. Verified against an exact bounded-knapsack brute force on ~800k random instances.
