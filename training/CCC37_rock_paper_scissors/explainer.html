一

Single duels

LEVEL 1 · LOOKUP TABLE

THE PROBLEM

Each line is one bout between two fighters, given by their styles (R, P or S). Print the style that wins. Rock beats Scissors, Scissors beats Paper, Paper beats Rock; if both share a style, that style goes through.

Input: N, then N lines of two letters. Output: N lines with the winning letter.

INPUT (example)
EXPECTED OUTPUT

  

  

  

    
KEY IDEA
A three-entry table BEATS = {R:S, S:P, P:R}. The left fighter wins if the styles match or if it beats the right one; otherwise the right fighter wins.

    
COMPLEXITY
O(N) time, O(1) extra memory.

    
PITFALLS
The arrows in the statement's diagram point from winner to loser (R→S, S→P, P→R). Read them the other way round and every answer flips.

  

  
solution.py · core
BEATS = {"R": "S", "S": "P", "P": "R"}  # key beats value

def winner(a, b):
    if a == b or BEATS[a] == b:
        return a
    return b

def solve(text):
    lines = text.split()
    n = int(lines[0])
    return [winner(s[0], s[1]) for s in lines[1:1 + n]]







  
二
Two rounds of the bracket
LEVEL 2 · SIMULATION

  

    

      
THE PROBLEM

      
Each tournament lists M fighters (a power of two) in first-round order. Neighbours fight (1st vs 2nd, 3rd vs 4th, …) and the winners keep their order for the next round. Report who is still standing after two rounds.

      
Input: N M, then N strings of M letters. Output: N strings of M/4 letters, in bracket order.

    

    
INPUT (example)
EXPECTED OUTPUT

  

  

  

    
KEY IDEA
One round is "zip the string in pairs and keep each pair's winner". Apply it twice, reusing the level-1 winner.

    
COMPLEXITY
O(N·M): each round halves the string, so two rounds touch 1.5·M fighters per tournament.

    
PITFALLS
Winners must stay in bracket order, and a tie keeps the shared style. A guard handles M < 4 (only one round possible).

  

  
solution.py · core
def play_round(s):
    return "".join(winner(s[i], s[i + 1]) for i in range(0, len(s), 2))

def solve(text):
    tokens = text.split()
    n = int(tokens[0])
    return [play_round(play_round(s)) if len(s) >= 4 else play_round(s)
            for s in tokens[2:2 + n]]







  
三
No Rock after round two
LEVEL 3 · SEARCH ON COUNT VECTORS

  

    

      
THE PROBLEM

      
Now we only know how many fighters of each style there are. Choose the first-round order so that after two rounds no Rock is left and at least one Scissors still stands. Any valid order is accepted and one always exists.

      
Input: N M, then N lines aR bP cS (a+b+c = M). Output: N arrangements of M letters using exactly those counts.

    

    
INPUT (example)
EXPECTED OUTPUT (one of many)

  

  

  

    
KEY IDEA
Positions don't matter, only counts: since we decide who meets whom, a round is just a matching ("3 R–P pairs, 1 S–S pair…") that maps a count vector to the next one. A DFS over rounds tries a heuristic matching first (Paper eats Rock, enemies cancel each other, Scissors stays safe), then seeded random perturbations, with a memo of dead states. The winning plan is turned into a string by nesting pairs into blocks.

    
COMPLEXITY
The search is tiny (two rounds over count vectors); building the string is O(M) per tournament.

    
PITFALLS
Our answer differs from the example on purpose: the statement accepts any valid order, so check.py re-simulates instead of diffing. Output lines must keep the exact counts.

  

  
solution.py · core (search + materialise, condensed)
def search(cnt, rounds_left, rng, failed, tries):
    if rounds_left == 0:
        return [] if goal(cnt) else None
    if cnt[S] == 0:
        return None
    key = (cnt, rounds_left)
    if key in failed:
        return None
    for m in candidates(cnt, rng, tries):   # heuristic first, then random
        nxt = next_counts(cnt, m)
        if nxt[S] == 0:
            continue
        sub = search(nxt, rounds_left - 1, rng, failed, tries)
        if sub is not None:
            return [m] + sub
    failed.add(key)
    return None

def materialize(styles_counts, plan):
    buckets = [[STYLES[i]] * c for i, c in enumerate(styles_counts)]
    for match in plan:
        nb = [[] for _ in range(K)]
        for (a, b), x in match.items():
            for _ in range(x):
                u, v = buckets[a].pop(), buckets[b].pop()
                nb[WIN[a][b]].append(u + v)     # the pair becomes one block
        buckets = nb
    return "".join("".join(b) for b in buckets)







  
四
Crown the Scissors
LEVEL 4 · FULL-BRACKET SEARCH

  

    

      
THE PROBLEM

      
Same counts as before, but now the whole tournament is played (log₂M rounds) and the last fighter standing must be a Scissors. Several orders work; any of them is accepted.

      
Input: N M, then N lines aR bP cS. Output: N arrangements of M letters whose champion is S.

    

    
INPUT (example)
EXPECTED OUTPUT (one of many)

  

  

  

    
KEY IDEA
The level-3 engine with a new goal: after every round the count vector must still contain a Scissors, and at the end it must be exactly one S. Rocks (the only enemy) are removed first by Paper, then by fighting each other. When the heuristic dead-ends, the DFS backtracks and, if needed, restarts with twice the random budget.

    
COMPLEXITY
O(rounds · tries) count operations plus O(M log M) to build the string; the largest input runs in about 0.3 s.

    
PITFALLS
Without the memo of failed (counts, rounds_left) states the retries blow up exponentially. Example output again differs by design (validated by check.py).

  

  
solution.py · core (goal + escalation)
def goal(cnt):
    if ROUNDS_LIMIT is None:                      # full tournament
        return cnt[S] == 1 and sum(cnt) == 1
    return all(cnt[i] == 0 for i in ENEMY) and cnt[S] >= 1

def solve_one(cnt, m):
    rounds = m.bit_length() - 1
    rng = random.Random(12345)
    tries = 8
    while True:
        failed = set()
        plan = search(tuple(cnt), rounds, rng, failed, tries)
        if plan is not None:
            return materialize(cnt, plan)
        tries *= 2                                   # widen the random budget







  
五
Enter Spock and Lizard
LEVEL 5 · FIVE STYLES

  

    

      
THE PROBLEM

      
Two new styles join: Spock (Y) and Lizard (L). Every style beats two others and loses to two. Arrange the given counts so that Scissors wins the full tournament.

      
Input: N M, then N lines aR bP cS dY eL. Output: N arrangements with champion S.

      S cuts P, P covers R, R crushes L, L poisons Y, Y smashes S, S decapitates L, L eats P, P disproves Y, Y vaporizes R, R crushes S.

    

    
INPUT (example)
EXPECTED OUTPUT (one of many)

  

  

  

    
KEY IDEA
Same count-vector search, generalised to 15 pair types. Scissors now has two enemies (Rock and Spock) and two "friends" that can kill them (Paper beats both, Lizard beats Spock). The heuristic orders pair types: friend kills enemy, enemy vs enemy, enemy halving, friendly ties, then the rest.

    
COMPLEXITY
Cheap for typical inputs; very skewed large cases (thousands of R and a handful of others) need many random tries, about 3–4 s for the whole level.

    
PITFALLS
The statement's diagram arrows are easy to misread; the quoted sentence is the reliable source for the ten "beats" pairs. Output differs from the example (multiple answers allowed).

  

  
solution.py · core (rules + heuristic order)
STYLES = "RPSYL"
BEATS = {'S': 'PL', 'P': 'RY', 'R': 'LS', 'L': 'YP', 'Y': 'SR'}
ENEMY = [IDX[c] for c in STYLES if "S" in BEATS[c]]   # R and Y

def key(p):
    a, b = p
    w = WIN[a][b]
    if a != b and (a in ENEMY) != (b in ENEMY) and w not in ENEMY:
        return 0  # friend kills enemy
    if a != b and a in ENEMY and b in ENEMY:
        return 1  # enemy vs enemy: net -1 enemy
    if a == b and a in ENEMY:
        return 2  # enemy halving
    if a == b:
        return 3  # friendly ties
    if w == S:
        return 4  # S eats someone
    return 5

HEUR = sorted(PAIRS, key=key)







  
六
Fill the free spots
LEVEL 6 · BRACKET DP ON WINNER SETS

  

    

      
THE PROBLEM

      
The bracket is already drawn (five styles), but some spots are marked X: we may put any style there. Choose them so that Scissors wins the tournament.

      
Input: N M, then N strings over R,P,S,Y,L,X. Output: the same strings with every X replaced by a style.

    

    
INPUT (example)
EXPECTED OUTPUT (one of many)

  

  

  

    
KEY IDEA
Bottom-up DP on the bracket tree. Each node keeps the family of possible-winner sets it can be steered into. Combining children: winners = ⋃ beat(a, b) over a∈L, b∈R. A smaller set is never worse, so only inclusion-minimal sets survive (≤ 10 bitmasks). If the root can reach exactly {S}, walk the back-pointers down and read off the X choices.

    
COMPLEXITY
O(M·A²) with A ≤ 10 masks per node and a precomputed 32×32 combine table: about 10 ms for a 4096-leaf bracket.

    
PITFALLS
Several fillings are valid; ties are broken with the preference order S, R, P, Y, L, which is why our answer can differ from the example (verified by check.py).

  

  
solution.py · core (leaves, combine, prune)
def leaf_options(c):
    if c == "X":  # we choose: any of the 5 styles (tie-break preference: S first)
        return {1 << IDX[ch]: ch for ch in "SRPYL"}
    return {1 << IDX[c]: c}

def prune(options):
    """Keep only the inclusion-minimal masks."""
    masks = sorted(options, key=lambda m: bin(m).count("1"))
    kept = []
    for m in masks:
        if not any((k & m) == k for k in kept):
            kept.append(m)
    return {m: options[m] for m in kept}

七
The adversary's spots
LEVEL 7 · EXISTS X, FOR ALL Z

  

    

      
THE PROBLEM

      
Besides our X spots there are Z spots: last-minute entrants whose style we cannot control, any of the five. Fill the X spots so that Scissors wins no matter who shows up in the Z spots. Z stays Z in the output.

      
Input: N M, then N strings over R,P,S,Y,L,X,Z. Output: X replaced, Z kept.

    

    
INPUT (example)
EXPECTED OUTPUT

  

  

  

    
KEY IDEA
The level-6 DP already reasons about sets of possible winners, so a Z leaf is simply the full set {R,P,S,Y,L}. Because Z choices in different subtrees are independent, the union-of-beats rule is the exact worst case. We still need the root to offer exactly {S}.

    
COMPLEXITY
Same as level 6: about 10 ms for a 4096-leaf bracket.

    
PITFALLS
Quantifier order: we fix X first, then the adversary picks Z. Z must stay literally Z. With the S-first preference the example is reproduced byte for byte.
